# OpenHands: полный базовый системный промпт на уровне Agent Profile

Локальный исходный патч для Canvas 1.20.0 + SDK/Agent Server 1.49.1.
Точные upstream commits, digest базового Docker-образа и SHA256 патчей — в `manifest.json`.
Рабочая установка этим каталогом автоматически не изменяется.

Последнее применение на рабочую установку: [DEPLOYMENT.md](DEPLOYMENT.md).

## Хранение и работа с репозиторием

Это отдельный репозиторий комплекта локальных патчей: он объединяет изменения
трёх upstream-проектов и рецепт совместной сборки. Канонические файлы — `patches/`,
`manifest.json`, `Dockerfile`, `scripts/`, Compose overlay и документация.
Upstream checkout, npm-кэш, образы и локальные отчёты в Git не входят.
Отложенные задачи — в [TODO.md](TODO.md), результаты исходной проверки —
в [VERIFICATION.md](VERIFICATION.md).

- `main` — проверенный комплект; каждое обновление сначала в ветке `upgrade/...`.
- Теги `local-system-prompt-vN` — сохранённые проверенные комплекты, а не признак
  их установки на сервер. Теги не передвигаем и не перезаписываем.
- После изменения исходников обновляем patch/hash, проверяем чистый перенос,
  сборку и тесты, затем коммитим и пушим комплект вместе с документацией.
- Установка на сервер отдельная: push не перезапускает сервисы.

После клонирования checkout upstream отсутствуют. Восстановить их в новом
рабочем каталоге можно из корня клона:

```sh
python3 scripts/manage.py prepare ../openhands-local-build
cd ../openhands-local-build
python3 scripts/manage.py build
python3 scripts/manage.py test
```

Рабочие `state`, `home`, `automation-home`, `secrets.env` и история разговоров
хранятся отдельно и требуют собственной резервной копии; этот Git-репозиторий
сохраняет код доработки и способ его воспроизведения.

## Поведение

В Customize → Agent profiles → редактирование OpenHands-профиля появляется
`Use a custom system prompt` и многострочное поле.

- Выключено (`system_prompt: null`): штатный базовый промпт SDK.
- Включено, текст заполнен: **замена**, а не суффикс базового промпта, текст дословно.
- Включено, поле пустое (`""`): пустая статическая основа.
- У каждого профиля своё значение; общие шаблоны не редактируются.
- Изменения относятся к новым разговорам. Сохранённые разговоры не переписываются.
- MCP, skills, AgentContext, runtime context и `system_message_suffix` остаются
  отдельными настройками. Дата/время в динамическом контексте этим патчем не меняются.
- ACP-профили не получают поле: их промптом управляет внешний агент.

Полный экспорт промпта из MCP можно вставить в это поле. Патч **не** генерирует
промпт и **не** меняет существующие `default` / `afpsy-corpus` или LLM-профили.

### Ограничение выбора модели

В upstream Canvas выбор другой LLM на главной может молча сбросить Agent Profile
и запустить общие `agent_settings`. Для профилей с собственным промптом это
заблокировано: Canvas покажет ошибку до создания разговора. Выберите LLM,
указанную в агентском профиле, либо измените LLM в профиле. Настройка полного
независимого выбора LLM при сохранении Agent Profile — отдельная доработка.
Для профиля `default` собственный промпт тоже работает, если выбранная LLM совпадает.

## Устройство патча

- `patches/sdk.patch`: поле в двух моделях, resolver → settings → Agent,
  сохранение при seed и тесты. Использует уже существующий `Agent(system_prompt=...)`.
- `patches/canvas.patch`: редактор, локальное расширение типов на API-границе,
  защита от сброса профиля, подписи на поддерживаемых Canvas языках и тесты. `node_modules` не изменяются.
- `patches/docs.patch`: описание расширения в SDK-документации, явно отмеченное как локальное.
- `Dockerfile`: пересборка frontend и установка SDK **вместе с соответствующим
  Agent Server из того же commit** поверх закреплённого образа. Upstream исполняемый
  файл `openhands-agent-server` содержит собственный Python (PyInstaller): простая
  установка SDK через pip не меняет его код. В нашем образе одноимённая команда —
  обычный запуск `python -m openhands.agent_server`, без правок бинарного архива,
  import hooks или runtime monkeypatch. Настройки запуска/аргументы сохраняются.

## Воспроизведение

Из этого каталога:

```sh
python3 scripts/manage.py verify
python3 scripts/manage.py build
python3 scripts/manage.py test
```

`verify` сверяет upstream commits и точный diff с патчами, отклоняет неизвестные
файлы и изменения. `build` только создаёт образ. `test` использует отдельный
контейнер без рабочих томов и ключей; API-тесты не вызывают LLM.

Чтобы повторить применение с нуля, укажите **несуществующий** каталог:

```sh
python3 scripts/manage.py prepare /tmp/openhands-prompt-reapply
cd /tmp/openhands-prompt-reapply
python3 scripts/manage.py build
python3 scripts/manage.py test
```

Подготовка скачивает ровно указанные commits, проверяет SHA256 патчей и выполняет
`git apply --check` до применения. Чужие checkout не перезаписывает.

## При обновлении upstream

1. Сохранить текущую версию этого Git-каталога и Docker-образ. Создать ветку обновления.
2. Выбрать совместимые версии Canvas и SDK/Agent Server; обновить **точные commits**,
   base image digest, Node digest при необходимости, имя custom image и Compose overlay.
3. Пробовать `prepare` в новом каталоге. Конфликт — повод пересмотреть код и тесты;
   **не** применять `--reject`, принудительные замены или автоматическое исправление.
4. Проверить, не появился ли аналогичный функционал upstream. Если появился,
   удалить ненужный патч и явно мигрировать данные, не держать два механизма.
5. После ручной адаптации обновить patch-файлы и их SHA256 в manifest. Выполнить
   `verify`, `build`, `test`, затем повторное чистое `prepare`. Проверить в браузере
   сохранение/повторное открытие, стандартный, пустой и пользовательский промпт;
   новый разговор должен показывать нужный System Message.
6. Проверить downgrade на копии данных и только затем менять рабочую установку.

После адаптации исходников патчи записываются так (HEAD каждого checkout должен
быть выбранным **чистым upstream commit**, локальные правки — в рабочем дереве):

```sh
git -C sources/sdk diff HEAD --binary --full-index > patches/sdk.patch
git -C sources/canvas diff HEAD --binary --full-index > patches/canvas.patch
git -C sources/openhands-docs diff HEAD --binary --full-index > patches/docs.patch
sha256sum patches/*.patch
```

Перенести новые SHA256 в `manifest.json`; новые файлы сначала добавить через
`git add -N`, иначе `git diff` их не включит. Сохранить обновлённый комплект
отдельным commit в этом каталоге. `verify` отклонит пропущенные незакоммиченные
файлы и несовпадающие hashes.

Успешное применение diff само по себе не доказывает совместимость новой версии.
Автообновления работающей установки здесь нет.

## Установка — отдельный шаг после согласования

Сначала остановить три сервиса и сделать согласованную резервную копию `state`,
`home`, `automation-home`, `compose.yaml`, `scripts` и `secrets.env` в закрытый каталог
(права 0700). Копия содержит ключи; не добавлять её в Git. Затем из
`/home/ae/services/openhands`:

```sh
docker compose -f compose.yaml -f customization/compose.custom.yaml up -d
```

Перезапускаются все три сервиса с одним custom image; production volume paths,
порты и tailnet остаются из основного compose. Проверить `/ready`, API профилей,
сохранение тестового профиля и новый разговор. После замены frontend обновить вкладку.
При будущих `up` использовать **оба** `-f`, иначе Compose вернёт upstream-образ.

## Откат

Старый AgentProfile использует `extra="forbid"`: даже `system_prompt: null` в JSON
не читается им. Поэтому одного переключения образа недостаточно.

Остановить server/canvas/automation; на **остановленной** установке выполнить:

```sh
python3 customization/scripts/rollback_profiles.py state/agent-profiles
python3 customization/scripts/rollback_profiles.py state/agent-profiles --write
docker compose -f compose.yaml up -d
```

Скрипт сначала сохраняет оригиналы в закрытый соседний каталог и удаляет только
`system_prompt` у OpenHands-профилей, сохраняя остальные поля, id и revision.
Повторный запуск безопасен. Расположение `state/agent-profiles` проверить перед
командой; если persistence path изменён — указать фактический каталог.
Общие настройки upstream игнорируют незнакомые поля. Разговоры не редактируются:
`Agent.system_prompt` поддерживался исходным SDK, уже созданные разговоры сохраняют
свой промпт. Новые разговоры после отката снова используют стандартный промпт.
Чтобы вернуть настройку профиля после повторной установки патча, брать только
нужные `system_prompt` из резервных JSON, не затирать более свежие профили целиком.
